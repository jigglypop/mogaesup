# Frontend AGENTS.md

`frontend/`는 캐릭터 목록·상세·작업 제어·파츠 미리보기·검수를 담당한다. UI 구현에 필요한 스택과 빌드 명령은 이 영역에서 관리한다.

## 렌더링 스택

- 사용자가 지정한 기준은 React Three Fiber, WebGPU, gaesup-world다. 현재 안정판 조합은 `@react-three/fiber 9.7.0`, `gaesup-world 1.0.30`, React 19.2, Three.js 0.178이며 정확한 버전은 package-lock.json으로 고정한다.
- 업그레이드 시 npm의 현재 버전과 peer dependency를 확인한다. gaesup-world와 맞지 않는 Three.js를 강제 설치하거나 R3F alpha를 안정판으로 취급하지 않는다.
- R3F가 render loop·camera·scene 수명을 소유하며 gaesup-world 공개 API로 world 설정을 연결한다. 임의 `WebGLRenderer`와 별도 animation loop로 되돌리지 않는다. `WebGPURenderer.init()` 완료 후 장면을 마운트하고 실제 backend가 WebGPU인지 확인한다.
- WebGPU 미지원 환경에서 호환 렌더러를 사용하면 화면에 구분해 표시한다. WebGL fallback으로 통과한 결과를 WebGPU 검증으로 보고하지 않는다.

## 화면과 API

- API 연결은 서버의 소유권·작업 영수증·idempotency 계약을 유지한다. 삭제된 계약 문서를 복원하지 않는다.
- 초기 약 5종은 서버의 목록으로 렌더링한다. A-E를 컴포넌트에 하드코딩하지 않는다. 진행률·막힌 이유·가능한 작업을 캐릭터별로 보여준다.
- 서버의 `next_actions`를 사용하며 미구현 기능을 활성화하지 않는다. 기술 검증과 사람의 시각 승인은 서로 다른 상태로 표시한다.
- 생성·리깅 제출은 대상·단계·유료 작업임을 사용자가 알 수 있는 실행 UI로 제공한다. 정상 실행마다 별도 확인창을 반복하지 않는다.
- API 클라이언트와 응답 타입은 한 곳에 둔다. provider key, Blender 연결정보, 서버 절대 경로를 번들·브라우저 저장소에 넣지 않는다. 폼 입력은 검증된 값이나 업로드 데이터로 API에 전달한다.

## 비동기 상태와 검수

- 제출 중 중복 클릭을 막고 같은 요청의 idempotency key를 유지한다. 응답을 잃으면 작업을 조회·복구하고 새 유료 제출을 자동 생성하지 않는다.
- 새로고침·재접속 시 서버에서 진행 중 작업을 복원한다. 페이지가 닫히면 구독·타이머를 정리한다. 클라이언트 오류를 provider 실패로 표시하지 않는다.
- 목록의 빈 상태, 로딩, 입력 오류, 서버 오류와 연결 끊김을 처리한다. 키보드로 폼·버튼을 사용할 수 있고 진행·오류를 식별할 수 있어야 한다.
- 파츠 토글과 애니메이션 미리보기는 버전이 명확한 산출물에 연결한다. GLB를 교체할 때 이전 렌더 자원을 해제한다. 승인 기록은 검토한 버전·증거와 함께 백엔드에 저장한다.

## 검증

현재 사용자 지시에 따라 `npm run build`만 수행하며 Playwright·실제 생성 검사는 실행하지 않는다. 빌드 결과로 실제 Meshy 성공이나 브라우저·시각 검수 완료를 주장하지 않는다.
